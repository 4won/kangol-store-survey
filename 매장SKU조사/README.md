# 매장 디스플레이 SKU 조사

매장이 링크로 들어와 현재 AW 시즌 DP(진열) 현황과 의견을 입력 → 응답이 **구글시트에 raw 행으로 누적**됩니다.

```
매장 폰/PC ──(GitHub Pages)──> 설문 입력 ──POST──> Apps Script ──> 구글시트(응답·제거요청·추가요청·원본JSON)
```

## 설문 구성 (6문항, 5단계 입력 + 제출)
| 단계 | 문항 |
|---|---|
| 매장 선택 | 채널형태 → 채널계열 → 매장명 선택상자 (선택 전에는 다음 단계로 못 넘어감) |
| DP 현황 | 1. 매장 SKU: 의류/가방/모자 × 실제 DP수 / 적정 DP수 (차이 자동 표시) · 2. 운영 SKU 수 의견: 카테고리별 5단계 (너무 많다 ~ 너무 모자르다) |
| 운영 실태 | 3. 과다 SKU 운영 실태(비공개 표시): 창고 적재 / 추가 DP / 기타(입력) · 4. 적정−실제 차이에 대한 방향: 제거 / 보유 / 추가 DP |
| 제거 품번 | 5. 의류·가방·모자 각 최대 10개 (처음 3칸, `+ 칸 추가`로 확장). 품번·상품명 일부만 입력해도 검색 |
| 추가 품번 | 6. 추가로 받고 싶은 품번. 같은 방식. 제거 품번으로 고른 상품은 검색에서 제외 |
| 제출 | 필수: 매장, 1번 6칸(실제·적정 DP수). 같은 매장이 다시 내면 최신 응답으로 대체 |

## 데이터 (이 폴더에 엑셀 2개를 두고 생성)
- `상품기초정보_2026AW.xlsx` : 품번 목록 (수입품번 기준 194개 = 의류 84 · 가방 69 · 모자 41. 기획명 `의류`·`의류(여성)` → 의류, `수입모자` → 모자)
- `매장리스트_전체_202610.xlsx` : 85개 매장 (백화점 50 · 쇼핑몰 14 · 아울렛 21)
```bash
cd 매장SKU조사
node tools/build_data.mjs        # 26AW/data/products.json · stores.json · apps-script/StoreList.gs 생성
```
> 엑셀 원본은 git 에 올리지 않습니다(.gitignore). 새 시즌은 `--season 27SS --products ... --stores ...` 로 생성합니다.

## 응답 수집 세팅 (최초 1회)
1. **새 구글시트**를 만든다 (상품반응도 시트와 별도)
2. 확장 프로그램 > Apps Script → `apps-script/Code.gs` 내용 붙여넣기, 새 파일 `StoreList` 에 `apps-script/StoreList.gs` 내용 붙여넣기
3. 함수 `setup` 실행 → 탭 4개 생성
4. 배포 > 새 배포 > 웹 앱 (실행: 나, 액세스: 모든 사용자) → URL 복사
5. `26AW/config.js` 의 `endpoint` 에 붙여넣고 push → 배포
> `endpoint` 가 비어 있으면 **테스트 모드**(제출 시 JSON 파일로 저장)입니다. 매장에 링크를 주기 전에 반드시 채우세요.
