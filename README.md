# 매장 반응도 조사 (26AW)

매장이 링크로 들어와 직접 선택·입력 → 응답이 **구글시트에 raw 행으로 누적** → 시트에서 복종별로 자동 취합.

```
매장 폰/PC ──(GitHub Pages: 26AW/)──> 설문 입력 ──POST──> Apps Script ──> 구글시트(raw 5탭 + 취합 4탭)
```

| 폴더 | 내용 |
|---|---|
| `26AW/` | **시즌 폴더** — 배포되는 설문 페이지 (`index.html`, `config.js`, `data/products.json`, `data/stores.json`, `img/`) |
| `apps-script/` | 응답 수집기 `Code.gs` (+ 생성되는 `StoreList.gs`) — 구글시트에 붙여 넣어 사용 |
| `tools/build_data.mjs` | 허브 데이터 → 상품 목록·이미지·매장 목록 생성 |

## 설문 구성
매장 선택(채널형태 → 채널계열 → 매장명 선택상자) → 시즌 전반 → **상품별 평가**(가방/의류/모자 탭, 세부 복종별 그룹) → 가격 적정선(주요 세부 복종 13개) → 경쟁브랜드(의류/모자 각 2곳) → 제출.
상품 카드: 이미지 + 판매가 + 등급 + 출고 색상, 디자인·가격 점수(1~5) + 한줄평.

## 데이터 생성 (상품·이미지·매장)
```bash
node tools/build_data.mjs --stores "C:/Users/-/Downloads/매장리스트_현재.xlsx"
```
- 기준: `kangol-work-hub/data/summary/index.json` 의 **최신 주차** productmap (`--week 2026-10-04` 로 지정 가능)
- 대상: **색상 중 하나라도 `출고완료`** 인 26AW 상품 (목록에는 출고된 색상만 표시)
- 등급: productmap 의 거래량등급, 없으면 `product-map-new/base.json` 값 (둘 다 없으면 표시 안 함)
- 이미지: `product-info-old/26AW/{품번}.jpg` (수입품번 → 품번은 `product-info.json` 매핑, 대시보드와 동일 규칙). 파일이 없는 상품은 "이미지 준비중" 표시
- 출고가 추가되면 위 명령을 다시 실행하고 push 하면 목록이 갱신됩니다. (이미 응답이 쌓인 후 상품이 바뀌어도 raw 의 품번·상품명은 그대로 보존)

## 1. 구글시트 + Apps Script 세팅 (최초 1회, 약 5분)
1. 새 구글시트 생성 (예: `26AW 매장반응도_raw`)
2. **확장 프로그램 > Apps Script** → `Code.gs` 내용 전체를 붙여 넣기, 새 파일 `StoreList.gs` 를 만들어 `apps-script/StoreList.gs` 내용을 붙여 넣기
3. 함수 선택 `setup` → **실행** (권한 승인) → 원본 5탭 + 취합 4탭이 생성됨
4. **배포 > 새 배포 > 유형: 웹 앱** → 실행 사용자 `나`, 액세스 권한 `모든 사용자` → 배포 → **웹 앱 URL 복사**
5. `26AW/config.js` 의 `endpoint` 에 URL 붙여 넣기
> `Code.gs` 를 수정하면 **배포 > 배포 관리 > 새 버전** 으로 다시 배포해야 반영됩니다. 시트는 비공개로 두세요(웹 앱 URL 은 쓰기 전용).

## 2. GitHub Pages 배포
1. 새 저장소 생성 후 이 폴더를 push (`main`)
2. 저장소 **Settings > Pages > Source: GitHub Actions** (워크플로가 `26AW/` 같은 시즌 폴더만 배포)
3. 배포 URL(`https://<계정>.github.io/<저장소>/`)을 매장에 배포
> 주의: GitHub Pages 는 공개 주소입니다. 상품 이미지·판매가(이미 출고된 상품)와 매장 목록이 공개되며, 원가 등 내부 수치는 포함하지 않습니다. 허브처럼 로그인 보호가 필요하면 Cloudflare Pages + Access 로 `26AW/` 를 올리는 방식으로 바꿀 수 있습니다(설문 코드 변경 없음, 단 매장 담당자 이메일 등록 필요).

## 취합 시트 (자동 수식, '최신' 제출만 집계)
| 탭 | 내용 |
|---|---|
| `복종별취합` | 가방/의류/모자별 응답 매장수·디자인·가격 평균, 적정가 하한/상한 중앙값, 경쟁대비 분포, **상품 한줄평 모음·가격 의견 모음** |
| `가격적정선취합` | 주요 세부 복종 13개별 적정가 하한/상한 중앙값·현재가 수준·경쟁 대비 분포·의견 |
| `세부복종별` | 복종 × 세부복종(백팩·아우터 등) 평균 점수 |
| `상품별취합` | 상품별 응답수·평균 점수 (디자인 높은 순) |
| `제출현황` | 71개 매장 제출/미제출, 전체 만족도 |
| `시즌응답` · `상품평가` · `가격적정선` · `경쟁브랜드` · `원본JSON` | **raw 누적** (한 행 = 한 매장×항목). 다른 곳에서 활용할 때는 이 탭을 읽으면 됨 |

- 같은 매장이 다시 제출하면 이전 행은 `최신=N` 으로 남고(삭제 없음) 새 행이 `최신=Y`. 집계는 Y 만 사용.
- raw 를 외부로 가져가려면: 시트 **파일 > 다운로드 > CSV**(탭별), 또는 시트 게시/Sheets API, BigQuery 연결 등. `상품평가` 탭은 `품번` 으로 productmap 과 바로 조인됩니다.

## 테스트
`26AW/config.js` 의 `endpoint` 가 비어 있으면 **테스트 모드** — 제출 시 서버 전송 없이 JSON 파일이 저장됩니다.
로컬 확인: `cd 26AW && npx serve` (또는 아무 정적 서버) 후 브라우저에서 열기.

## 알아둘 점
- 인증 없는 공개 링크라 악의적 제출이 가능합니다. 방어: 매장명이 목록에 없으면 거부, 봇 허니팟, 응답은 raw 로 남고 `최신` 으로만 집계. 필요하면 `Code.gs` 에 공통 접속코드 검사를 추가할 수 있습니다.
- 응답 도중 새로고침해도 입력은 기기(localStorage)에 임시 저장됩니다. 제출 성공 시 삭제.
- 시트 셀당 5만 자 제한 때문에 `원본JSON` 은 49,000자에서 잘립니다(정규화 탭에는 전체 저장).
